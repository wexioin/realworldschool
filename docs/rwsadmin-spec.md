# rwsadmin.fingr.io 구조 분석 (구현용 spec)

원본: https://rwsadmin.fingr.io — Ruby on Rails + Hotwire(Turbo/Stimulus), Tailwind, Pretendard, Tabler Icons.
관리자 계정으로 전 페이지 탐색 후 정리. 이 문서는 erp-v2에 재구현하기 위한 기준 문서.

---

## 1. 역할과 진입점

| 역할 | 로그인 후 진입 | 접근 범위 |
|---|---|---|
| 어드민 | `/contents` | 전체 (사이드바 전 메뉴) |
| 검수자 (reviewer) | `/review/assignments` | 배정된 2차 검수만 |
| 크리에이터 (creator) | `/my/contents` | 본인 제출 콘텐츠 + 지급 정보 |

가입(`/signup`)은 크리에이터·검수자만 셀프 가능. 어드민은 운영자가 부여.
가입 필드: 이름, 역할, 이메일, 소속, 비밀번호(8자 이상).

## 3. 검수 파이프라인 (핵심 데이터 플로우)

부제: **제출 → AI 1차 검수 → 전문가 2차 검수 → 최종 승인 → 지급 → 출시**

### review_status (11 상태)
| 값 | 라벨 |
|---|---|
| `first_review_pending` | 1차 검수 대기 |
| `first_revision_requested` | 1차 수정 요청 |
| `reviewer_assignment_pending` | 2차 검수자 배정 대기 |
| `second_review_pending` | 2차 검수 대기 |
| `second_revision_requested` | 2차 수정 요청 |
| `final_approval_pending` | 최종 승인 대기 |
| `approved` | 검수완료(통과) |
| `rejected` | 반려 |
| `payment_pending` | 지급예정 |
| `paid` | 지급완료 |
| `released` | 출시 |

### 심사 관리 탭 (`/reviews?tab=`)
`all` 전체 / `first_review` 1차 검수(AI) / `assignment` 검수자 배정 / `second_review` 2차 검수 /
`revision` 수정 요청 / `final_approval` 최종 승인 대기 / `approved` 검수완료(통과) /
`payment` 지급 예정 / `release` 출시 예정 / `released` 출시 완료 / `rejected` 반려

### 단계별 어드민 액션
| 단계 | 액션 | 비고 |
|---|---|---|
| 1차 검수(AI) | `AI 1차 검수 실행` 버튼 | |
| 검수자 배정 | 검수자 지정 | |
| 2차 검수 | (액션 없음 — 검수자가 수행) | |
| 수정 요청 | 없음 | "크리에이터의 수정 완료 제출을 기다리는 중입니다." |
| 최종 승인 대기 | `최종 승인`(승인 메모 선택) / `반려`(사유 필수, 크리에이터 전달) | 지급정보 없으면 승인 후 검수완료(통과)에서 대기 |
| 검수완료(통과) | `지급예정으로 전환` | 지급 정보 **3종 완비** 필요 |
| 지급 예정 | `지급 처리` → 지급일 입력 → `지급 완료로 기록` | 금액은 별도 정산 시스템. 수익 배분율 30.0% |
| 반려 | 없음 | |

### 카드 공통 구성
제목 · `크리에이터 · 카테고리 · 학년 · 가격 · 제출 YYYY년 M월 D일`
링크: `스튜디오` `기획서(PPT)` `기획서(Word)` `운영 가이드` `상세`

### 2차 검수 루브릭 (`/review/assignments/:id`) — 확정
**가중 배점 (5항목 합계 100점, 80점 이상 통과)**

| 항목 | 필드 | 배점 |
|---|---|---|
| 교육과정 적합성 | `scores[curriculum]` | 25 |
| 콘텐츠 완성도 | `scores[content_quality]` | 25 |
| 저작권·개인정보 처리 | `scores[copyright_privacy]` | 20 |
| 운영 용이성 | `scores[operability]` | 15 |
| 시장성 | `scores[marketability]` | 15 |

- `검수 의견` (`review_note`, textarea) — "이 내용은 크리에이터에게 그대로 전달됩니다."
- 제출 버튼: `검수 결과 제출`
- 안내: "80점 이상이면 최종 승인 대기로, 미만이면 크리에이터에게 **수정 요청(마감 1주)** 이 나갑니다."
- 서버 `SecondReview.total_from`이 재계산 (클라이언트는 표시 전용)
- Stimulus `rubric_controller`: targets `score`/`total`/`verdict`, `passMark: 80`, 미통과 시 `통과까지 N점`
- 상단에 검수 대상 정보(콘텐츠 유형·교과·주제·수업형태·수업시간·학습목표·설명·준비물) + 자료 링크 4종

### 2차 검수자 배정 UI (`/reviews?tab=assignment`)
- 버튼 `2차 검수자 배정` → 폼 전개
- `검수자 선택` 드롭다운: **담당 카테고리 일치 검수자를 진행중 건수 오름차순으로 우선 추천**
  (표기: `박검수 (한국교육대학교) · 진행중 1건`), 그 아래 전체 검수자 목록
- 마감일 date input — **기본값 = 배정일 + 2주**
- 제출: `배정하고 안내 메일 발송`
- 안내문: "교과 연계형 담당 검수자 중 진행 중인 배정이 적은 순서로 추천했습니다." / "마감일은 배정일 기준 2주가 기본값입니다."

### 2차 검수 진행중 카드 (어드민)
`{검수자명}님이 2차 검수를 진행 중입니다.` + `마감 YYYY년 M월 D일 · N일 남음`

## 3-B. ERD (DFD 문서 기준)

검수 이력은 **단계별로 테이블이 분리**돼 있음 (하나의 review 테이블이 아님).

```
어드민       어드민_ID(uuid) 어드민명 직책(dropdown) 소속 이메일 연락처
크리에이터   크리에이터_ID(uuid) 크리에이터명 크리에이터_유형(dropdown) 소속 소속학교/기관
             연락처 이메일 ★주민등록번호 ★주소 ★계좌번호
검수자       검수자_ID(uuid) 검수자명 검수자유형(dropdown) 소속 연락처 이메일
콘텐츠       프로젝트_ID(uuid) 등급 상태 콘텐츠명 콘텐츠유형 크리에이터_ID 제출일
             대상학년 교과 주제 역량 인원 콘텐츠설명 수업형태 수업시간(분) 가격(원)
             핵심역량 학습목표 준비물·시스템구성품 검수상태 출시일 판매상태
             수익배분율(%) 계약체결여부 비고 상태변경시간
             스튜디오링크 기획서_ppt_링크 기획서_word_링크 운영_가이드 지급일

1차 검수 내용  검수_ID(uuid) 콘텐츠_ID 검수일 통과여부(bool) 검수내용
2차 검수 내용  검수_ID(uuid) 검수자_ID 콘텐츠_ID 배정일 마감일 검수일
               검수내용 통과여부(bool) 수정마감일
검수 완료 내용  검수_ID(uuid) 어드민_ID 콘텐츠_ID 검수일 검수내용
반려 내용      검수_ID(uuid) 어드민_ID 콘텐츠_ID 검수일 검수내용
```

★ = 지급 정보 3종. 이 3개가 모두 채워졌는지가 `검수완료(통과)` ↔ `지급예정` 분기 조건.

## 3-C. 상태 전이 규칙 (DFD 기준, 구현의 정본)

| # | 트리거 | 조건 | 부수 효과 | 결과 상태 |
|---|---|---|---|---|
| 1 | `AI 1차 검수 실행` | 통과 | 1차 검수 내용 row 생성 (검수내용·통과여부·검수일=당일) | `2차 검수자 배정 대기` |
| 2 | `AI 1차 검수 실행` | 미통과 | 위와 동일 | `1차 수정 요청` |
| 3 | `2차 검수자 배정` | — | 2차 검수 내용 row 생성 (검수자_ID·마감일·배정일=당일) | `2차 검수 대기` |
| 4 | 검수자 `검수 결과 제출` | 총점 **≥ 80** | 2차 검수 내용에 통과여부=yes, 검수내용, 검수일 기록 | `최종 승인 대기` |
| 5 | 검수자 `검수 결과 제출` | 총점 **< 80** | 통과여부=no + **수정마감일 = 검수일 + 7일** | `2차 수정 요청` |
| 6 | 크리에이터 `수정 완료` | 직전이 `1차 수정 요청` | — | `2차 검수자 배정 대기` |
| 7 | 크리에이터 `수정 완료` | 직전이 `2차 수정 요청` | — | `최종 승인 대기` |
| 8 | 어드민 `최종 승인` | 지급정보 3종 완비 | 검수 완료 내용 row 생성 | `지급예정` |
| 9 | 어드민 `최종 승인` | 지급정보 미완비 | 검수 완료 내용 row 생성 | `검수완료(통과)` |
| 10 | 어드민 `반려` | — | 반려 내용 row 생성 (사유 필수) | `반려` |
| 11 | 크리에이터 `개인정보 입력` | 주민번호·주소·계좌 제출 | 크리에이터 row에 저장 | `지급예정` |
| 12 | 어드민 `지급 처리` | — | **지급일 = 당일** | `지급완료` |
| 13 | 어드민 `출시` | 출시 가격 입력 | **가격(원)을 출시 가격으로 갱신** | `출시` |

> 수정 요청 화면에서 수정 마감일은 **검수일 + 1주일로 자동 설정**.
> 검수자 배정 화면에서 검수 마감일은 **배정일 + 2주가 기본값**(사용자 변경 가능).

### 크리에이터 화면 — 상태별 안내문 · 처리 버튼

| 검수상태 | 안내문 | 처리 버튼 |
|---|---|---|
| 1차 검수 대기 | 1차 AI 검수가 진행될 예정입니다. | — |
| 1차 수정 요청 | (검수 의견 노출) | **수정 완료** |
| 2차 검수자 배정 대기 | 2차 검수자가 매칭될 예정입니다. | — |
| 2차 검수 대기 | 검수자가 2차 검수를 진행 중입니다. | — |
| 2차 수정 요청 | (검수 의견 노출) | **수정 완료** |
| 최종 승인 대기 | 모든 검수가 완료되어 최종 승인을 대기 중인 콘텐츠입니다. | — |
| 검수완료(통과) | 크리에이터 페이지에서 요청된 개인정보를 입력해 주시기 바랍니다. | **개인정보 입력** |
| 지급예정 | 검수를 완료하여 지급이 예정인 콘텐츠입니다. | — |
| 지급완료 | 지급이 완료된 콘텐츠입니다. | — |
| 출시 | 출시된 콘텐츠입니다. | — |
| 반려 | (반려 사유 노출) | **버튼 없음** |

`개인정보 입력` 모달 필드: 주민등록번호 / 주소 / 입금될 계좌번호 → `제출`

## 5. Content 스키마 (`/contents/new` 폼 기준)

```
content_name*      콘텐츠명
code               콘텐츠 코드 (예: D-03)
content_type       콘텐츠 유형 (AR 체험, QR 미션 …)
creator_id         크리에이터 (자체 개발 = 없음)
origin_type        개발 유형: 오리지널 | 크리에이터 | 파트너
category_group     대분류: 미분류 | 교과 연계형 | 역량 중심형 | 창의·예술형 | 특수목적형
category_id        세부 카테고리 (아래 23종)
competency_ref_id  핵심역량 (교육부 6대)
target_grade       대상 학년
subject            교과
topic              주제
competency         역량 (자유입력)
core_competency    핵심역량 (자유입력)
class_format       수업 형태 (실내형 …)
participants       수업 인원
duration_min       수업 시간(분)
grade              등급: 미지정 | S | A | B | C
description        콘텐츠 설명
learning_goal      학습 목표
materials          준비물 · 시스템 구성품
note               비고
review_status      검수 상태 (11종)
sale_status        판매 상태: 준비중 | 판매중 | 판매 중지 | 판매 종료
price              가격(원)
revenue_share_pct  수익 배분율(%)  — 기본 30.0
progress_pct       개발 진행률(%)
submitted_at       제출일 (datetime)
released_at        출시일
paid_at            지급일
contract_signed    계약 체결 완료 (bool)
studio_link / plan_ppt_link / plan_word_link / ops_guide_link
```

크리에이터 제출 폼(`/my/contents/new`)은 축소판 + 파일 업로드:
`plan_ppt_file`, `plan_word_file` (PPT·Word·PDF, 20MB 이하)
