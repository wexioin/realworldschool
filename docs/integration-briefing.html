0. 지금까지 만든 것 (Admin ERP)

페이지·역할·파이프라인은 준비됨. 데이터만 Mock → 실연동으로 바꾸면 됩니다.

역할 화면 완료 · Mock 어드민 / 검수자 / 크리에이터 로그인·메뉴·액션 분기

2. 콘텐츠 등록 — Studio → Admin

수동 등록을 없애고, 스튜디오에서 제작 중인 콘텐츠가 Admin 검수 파이프라인에 들어오게 하려는 단계입니다.

우리가 밀고 싶은 방향 어드민에서 콘텐츠를 일일이 등록하지 않습니다. 리얼월드 스튜디오의 티처스 요금제를 구독한 회원과 그 콘텐츠가 웹훅(또는 동등한 API)으로 Admin 「콘텐츠 자산」에 자동으로 뜨게 하고 싶습니다. 다만 Studio 회원가입은 이메일만 받기 때문에 이름·학교·전화 등 상세정보가 없습니다. 그래서 realworld-school.org에서 상세정보를 기입하고, Studio에서 받은 게임 ID로 콘텐츠를 신청하는 방안을 선호합니다.

A. Studio 직연동 (웹훅)

티처스 구독 회원 + 콘텐츠 → Admin 콘텐츠자산 자동 생성.

이슈 Studio에는 이름·학교·전화 없음

B. School.org 신청 (선호)

School.org에 상세정보 기입 + 게임 ID로 콘텐츠 신청 → Admin/검수 연결.

이슈 “이미 신청된 게임”으로 신청이 막힘

추가 확인 요청 realworld-school.org에서 수동으로 콘텐츠 신청을 하지 않아도, 스튜디오에서 개발 중인 콘텐츠가 School.org(및 Admin)와 자동으로 연동되는 방법이 있는지 확인해 주세요. 또한 오리지널/개인 구분 기준, 오리지널 신청·배정 방식, 기획서·운영가이드 업로드 경로에 대한 업무 지식이 부족하니 이 부분도 elaborate 부탁드립니다.

역할별 가입 화면을 만들었고, 크리에이터 연동 방식은 아래 권장안을 기본값으로 두었습니다.

역할가입 방식가입 시 수집
어드민 이메일 — @e-redpoint.com 만 허용 이름, 휴대폰, 소속/팀, 비밀번호
검수자 이메일 직접 가입 이름, 휴대폰, 소속, 전문분야, 유형, 담당 카테고리(A–D)
크리에이터 권장 School.org(프로필) + Studio(콘텐츠) 이중 연결 유형, 학교/기관, 전화, Studio·School 이메일, 지급정보(주민·주소·계좌)
왜 School.org를 프로필 정본으로 권장하는가 Studio는 가입 시 이메일만 받아 이름·학교·전화를 알 수 없습니다. School.org는 상세 프로필이 있고, 게임 ID 신청과도 맞습니다. 다만 콘텐츠·티처스 자동 유입은 Studio 쪽이 정본이므로 양쪽 이메일을 모두 저장해 매칭 키로 씁니다.

7. 미팅에서 꼭 받아올 것

체크하며 진행하면 다음 스프린트 착수 조건이 명확해집니다.

  • Studio 웹훅/API — 가능 여부, 이벤트 목록, 담당 엔지니어/문서
  • 티처스 필터 기준 — 어떤 구독/콘텐츠가 Admin으로 올지
  • School.org 「이미 신청된 게임」 — 원인 + 자동연동 대안 유무
  • 오리지널 업무 플로우 — 신청·배정·기획서/가이드 업로드 주체와 위치
  • 오리지널/개인 구분 규칙 — 시스템 필드 또는 운영 규칙
  • AX팀 컨택 — 판매 실적 API 스펙·식별자 매핑
  • School.org 출시 절차/API — Admin 출시 버튼이 호출할 대상
